# UI 设计：服务信息页「Pod 重启」

> 视觉规范，供步骤 3/4 实现对齐。整体沿用项目既有亮色主题与 Element Plus 风格。

## 一、卡片「重启」按钮（黄色）

位置：`.svc-card-actions` 内，「环境变量」按钮**之后**追加。

```
[日志] [日志目录] [Nacos配置] [环境变量] [重启]   ← 黄色
                                      ▲ type="warning"
```

- 样式：`<el-button link type="warning" size="small">`，黄色文字链接按钮，与同排其他 `link type="primary"` 按钮高度、间距一致。
- loading 态：按服务 `restarting[svc.name]` 控制，加载中转圈并禁用，防止重复点击。

## 二、工具栏「重启全部服务」按钮（红色危险）

位置：工具栏现有「快捷部署」等按钮旁。

```
… [[ 快捷部署 ]]  [⟳ 重启全部服务]
                  ▲ type="danger" plain size="small"，红色描边按钮
```

- 仅当 `selectedProject && selectedEnv` 选中时显示/可用，未选齐隐藏或灰显（与工具栏现有 `v-if` 风格一致）。
- `loading` 态：`restartingAll` 控制整钮 loading。

## 三、二次确认弹窗

两处操作均用 `ElMessageBox.confirm`，`type` 与按钮色呼应：

| 操作 | 弹窗 type | 标题 | 文案要点 | 确认/取消按钮 |
|------|-----------|------|----------|---------------|
| 单服务重启 | `warning` | 重启服务 | 确定重启服务「{svc.name}」吗？其内部 Pod 会滚动重建，期间可能短暂不可用。 | 「确定重启」/「取消」 |
| 重启全部服务 | `warning`（按钮为危险色） | 重启全部服务 | 将对该命名空间下**所有服务（所有 Pod）**执行滚动重启，全部服务会短暂不可用，确定继续？ | 「确定重启全部」/「取消」 |

## 四、结果反馈

- 成功：`ElMessage.success`（如「已触发 服务名 重启」）；
- 「重启全部服务」存在个别失败：`ElMessage.warning` 汇总 `X 个成功 / Y 个失败（失败清单）`；
- 整体失败 / 请求异常：`ElMessage.error(res.msg)`。
- 完成后触发刷新，观察 pod 重建（期间状态短暂 Pending → Running）。

## 五、图标与配色基线

- 图标用 emoji（⟳ / 或内联 SVG），**不引入图标库**。
- 黄色警示 `#e6a23c`（`type="warning"`）、危险 `#f56c6c`（`type="danger"`）、主色 `#409eff`，与项目现有配色一致；产品流程沿用 `svc-*` 系列样式与 `svc-card-actions` 按钮布局。

## 六、交互态

| 状态 | 表现 |
|------|------|
| 未确认取消 | 不触发任何请求，loading 不置位 |
| 请求进行中 | 对应按钮 loading + 禁用，防重复点击 |
| 成功 | 绿色浮层提示，随后刷新卡片体现重建 |
| 失败（含个别失败） | 红色/黄色浮层提示具体原因，页面状态不丢失 |
| 重建过程 | 卡片状态短暂 Pending 后恢复 Running，属预期 |
