# 开发指南

> 面向开发者：说明代码分层约定、如何新增模块与接口、统一响应、权限与审计、数据库迁移、前端约定。

## 代码组织

后端为 Flask 单体应用，按业务域拆分为 `modules/<域>/`，每个模块自包含。核心跨域能力收敛在 `core/`。

```text
modules/<域>/
├── __init__.py
├── routes.py        # Blueprint 定义 + register(app)
├── models.py        # SQLAlchemy 数据模型
├── api.py 或 api/   # 接口处理函数（薄层，调 service）
└── service.py 或 services/  # 业务逻辑
```

分层约定：路由/接口层负责参数解析与响应，业务逻辑放 service 层，数据模型放 models，避免接口层堆业务代码。

## 新增一个模块

1. 新建 `modules/<域>/` 目录，含 `__init__.py`、`routes.py`、`models.py`、`api.py`（或 `api/`）、`service.py`（或 `services/`）。
2. 在 `routes.py` 中定义 Blueprint 并暴露 `register(app)`：

```python
from flask import Blueprint

xxx_bp = Blueprint('xxx', __name__)


def register(app):
    app.register_blueprint(xxx_bp, url_prefix='/api/xxx')
```

3. 在 `app.py` 中导入并加入 `MODULES` 列表，框架会自动遍历调用 `register(app)`。

## 新增一个接口

1. 在 `routes.py` 注册路由（或用 `add_url_rule`）：

```python
xxx_bp.add_url_rule('/list', 'xxx_list', xxx_list, methods=['GET'])
```

2. 在 `api.py` 写处理函数，用统一响应返回：

```python
from core.response import success_response, error_response
from core.security import require_permission


@require_permission('page:xxx')
def xxx_list():
    items = []
    return success_response(items)
```

3. 错误处理：失败返回 `error_response('错误描述', 500)` 或对应业务码。

## 统一响应格式

所有接口统一使用 `core/response.py`：

```json
{ "code": 200, "msg": "success", "data": null }
```

- 成功：`success_response(data, msg='success')`。
- 失败：`error_response(msg, code=500, data=None)`，HTTP 状态码与 code 一致。

## 权限控制

- 用 `@require_permission('perm_code')` 装饰接口，要求当前角色拥有该权限码。
- 多权限任一满足用 `@require_any_permission('a', 'b')`。
- 权限码定义在 `modules/system/permissions.py`（`ALL_PERMISSIONS` / `BUILTIN_ROLES`）。
- 页面权限用 `page:xxx`，操作权限用 `op:xxx`。
- 超级管理员仅放行系统管理权限集，其余接口自动 403（全局钩子已处理）。

## 审计

- 全局拦截器自动记录所有写操作（POST/PUT/DELETE），无需手动调用。
- GET/HEAD/OPTIONS 不记录；SSE、Agent 心跳、审计自身、认证接口由各自机制处理。
- 敏感字段（密码/密钥/token/kubeconfig 等）自动脱敏。
- 需要字段级 diff 时，在关键更新接口显式调用 `build_diff`。
- 认证事件（登录/登出）用 `record_auth_event` 显式记录。

## 数据模型与迁移

- 模型继承 `db.Model`，`db` 从 `core.db` 导入（全局共享实例）。
- 表结构变更在 `core/bootstrap.py` 启动时自动做字段级迁移（新增字段安全追加，不做破坏性变更）。
- 新增表后无需手动建表，启动自动创建。
- 模型提供 `to_dict()` 供接口返回，敏感字段默认不返回明文。

## 配置与连接

- 启动必需配置（MySQL/Redis/端口）在 `config/config.yaml`，通过 `config.config` 访问。
- 业务配置（NFS/Harbor/K8s 等）从 MySQL `settings` 表读取，不要硬编码或读环境变量。
- Redis 通过 `core/redis_client.py` 的 `safe_*` 封装调用，必须考虑降级。

## 前端约定

- 前端为 Vue 3（CDN）+ Element Plus 单页应用，页面 JS 位于 `static/js/modules/<域>/`。
- 新增页面 JS 后需在 `templates/base.html` 引入（`static_asset()` 自动带版本号，改文件后自动拉新缓存）。
- HTML 页面不缓存（`after_request` 已设置 no-cache），避免旧页面结构导致组件未定义。
- SSE 接口需注意鉴权：EventSource 无法自定义 Header，token 走 `?token=` query 参数。
- 前端页面权限与菜单由 `menus` 表统一驱动，通过 `GET /api/menus` 获取。

## 检查清单

- 接口使用统一响应格式。
- 写操作接口有权限码装饰。
- 敏感字段不在响应/审计/日志中泄漏明文。
- 业务配置从 settings 读取，不硬编码。
- Redis 调用有降级路径。
- 新增页面 JS 已在 base.html 引入。
- 相关文档（模块手册、API 文档、数据字典）同步更新。
