## 1. 部署流程概述

### 1.1 部署模式

| 模式 | 说明 | 适用场景 |
|------|------|--------|
| **复制模式** | 从源环境复制 Nacos 数据到目标环境 | 新建相同配置的环境 |
| **新建模式** | 创建全新的环境，不复制数据 | 从零开始创建环境 |

## 2. 复制模式流程

### 2.1 流程说明

复制模式是从**源环境**复制必要数据到**目标环境**，包括：

1. **Nacos 数据目录** - 从源环境复制 nacos 数据到目标环境
2. **MySQL 数据** - 在 k8s 阶段 MySQL 启动后复制（✓已实现）

### 2.2 数据源映射

| 数据类型 | 源位置 | 目标位置 | 时机 |
|---------|--------|---------|------|
| Nacos数据 | `/data/project/datastorg/{project}/{source}/nacos` | `/data/project/datastorg/{project}/{dest}/nacos` | Step 4 |
| MySQL数据 | 源环境 MySQL PVC | 目标环境 MySQL PVC | Step 7 (MySQL启动后 ✓已实现) |

### 2.3 复制策略

| 数据类型 | 复制方式 | 说明 |
|---------|---------|------|
| Nacos数据 | `cp -r` (SSH) | 复制 nacos 目录到目标环境 |
| MySQL数据 | `cp -r` (SSH) | MySQL 启动后停止，复制 PVC 数据，再启动 |

### 2.4 注意事项

1. **Nacos数据** - 复制后 Nacos 启动时会自动加载数据
2. **MySQL数据** - 必须先启动 MySQL 生成 PVC 目录，然后停止 MySQL，复制数据，再启动
3. **端口** - 新环境使用不同的端口段
4. **域名** - 新环境使用独立域名

## 3. 新建模式流程

### 3.1 流程说明

新建模式是创建一个**全新的环境**，不复制任何数据。

### 3.2 与复制模式的区别

| 步骤 | 复制模式 | 新建模式 |
|------|---------|--------|
| 生成YAML | ✅ | ✅ |
| 创建NFS目录 | ✅ | ✅ |
| 复制Nacos数据 | ✅ | ❌ |
| 复制MySQL数据 | ✅ (k8s阶段 ✓已实现) | ❌ |
| 创建Harbor项目 | ✅ | ✅ |
| k8s操作 | ✅ (✓已实现) | ✅ (✓已实现) |

### 3.3 新建模式后需要手动处理

1. **Nacos配置** - 手动导入配置文件
2. **数据库** - 手动执行建表SQL
3. **业务数据** - 手动导入初始数据

## 4. 详细步骤说明

### 4.1 Step 1: 保存配置到数据库

**操作内容**

| 操作 | 说明 |
|------|------|
| 保存项目 | 创建或更新项目记录 |
| 保存环境 | 创建环境记录，包含域名、端口、nacos_namespace 等 |
| nacos_namespace | 新建项目从系统设置读取默认值，新增环境从源环境继承 |

### 4.2 Step 2: 生成 YAML 配置文件

**生成的文件类型**

| 文件类型 | 数量 | 说明 |
|---------|------|------|
| Deployment | N | 每个微服务一个 |
| Service | N | 每个微服务一个 |
| ConfigMap | 1 | 公共配置 |
| 中间件 | N | nacos/mysql/redis/rabbitmq 等 |

**文件输出目录**

```
./product/{project}-{env}/
├── deployment/
│   ├── {project}-app.yaml
│   └── ... (N个文件)
├── service/
│   ├── {project}-app.yaml
│   └── ... (N个文件)
├── middleware/
│   ├── nacos.yaml
│   ├── mysql.yaml
│   └── ...
└── public-config.yaml
```

### 4.3 Step 3: 创建 NFS 目录结构

**目录结构**

```
/data/
├── logs/
│   └── {project}-{env}/
│       ├── {project}-app/
│       └── ... (每个服务一个目录)
├── project/
│   ├── {project}/
│   │   └── {env}/
│   │       ├── template/
│   │       ├── upload/public/
│   │       ├── key/
│   │       └── yiqianbao/
│   └── ops/
│       └── {project}-{env}/
└── datastorg/
    └── {project}/
        └── {env}/
            ├── redis/
            └── nacos/
```

### 4.4 Step 4: 复制 Nacos 数据 (仅复制模式)

**复制内容**

| 数据 | 源 | 目标 | 方式 |
|------|-----|------|------|
| Nacos数据 | `/data/project/datastorg/{project}/{source}/nacos` | `/data/project/datastorg/{project}/{dest}/nacos` | `cp -r` (SSH) |

**不复制的内容**

| 数据 | 原因 |
|------|------|
| 服务日志 | 新环境启动后自动生成 |
| 公共数据目录 | 新环境独立管理 |
| MySQL数据 | 需在 k8s 阶段 MySQL 启动后复制 |

### 4.5 Step 5: 创建 Harbor 项目

**创建内容**

| 操作 | 说明 |
|------|------|
| 创建项目 | `{project}-{env}` |
| 配置清理策略 | 保留最近3个版本 |
| 设置定时任务 | 每小时执行清理 |

### 4.6 Step 6: k8s 创建 Namespace (✓已实现)

**创建内容**

| Namespace | 用途 |
|-----------|------|
| `{project}-{env}-middleware` | 中间件资源 |
| `{project}-{env}-service` | 微服务资源 |

**执行方式**

```bash
# 在 k8s master 上通过 SSH 执行
kubectl create namespace {project}-{env}-middleware
kubectl create namespace {project}-{env}-service
```

### 4.7 Step 7: 启动中间件 (✓已实现)

**启动顺序**

```
1. 启动所有中间件 (kubectl apply middleware/*.yaml)
   ↓ 等待所有中间件启动完毕
2. 停止 MySQL (kubectl scale statefulset mysql --replicas=0)
   ↓ 等待 MySQL 完全停止
3. 复制源环境 MySQL 数据到目标环境
   ↓ 复制 PVC 数据 (sync_mysql_pvc_data)
4. 启动 MySQL (kubectl scale statefulset mysql --replicas=1)
   ↓ 等待 MySQL 启动并健康检查通过
5. 确认所有中间件健康检查通过
```

**中间件健康检查**

| 中间件 | 检查方式 | 端口 |
|--------|---------|------|
| Nacos | HTTP GET /nacos/v1/console/health | 8848 |
| MySQL | mysqladmin ping | 3306 |
| Redis | redis-cli ping | 6379 |
| RabbitMQ | HTTP GET /api/health/checks/alarms | 15672 |

### 4.8 Step 8: 启动微服务 (✓已实现)

**启动方式**

```bash
# 应用所有 Deployment + Service
kubectl apply -f {project}-{env}/deployment/
kubectl apply -f {project}-{env}/service/
# 等待服务健康检查通过
```

## 5. 异常处理

### 5.1 常见错误

| 错误类型 | 说明 | 处理方式 |
|---------|------|--------|
| 目录创建失败 | NFS服务器不可达 | 检查NFS连接 |
| Nacos复制失败 | 源目录不存在 | 检查源环境是否已部署 |
| Harbor创建失败 | 项目已存在 | 跳过创建 |

### 5.2 错误日志

所有步骤日志写入 `logs/{project}/{project}-{env}-{action}.log`，可通过 SSE 实时查看。

### 5.3 重试机制

| 操作 | 重试次数 | 间隔 |
|------|---------|------|
| SSH连接 | 3次 | 5秒 |
| 目录创建 | 3次 | 2秒 |

## 6. 回滚机制

### 6.1 回滚条件

- 部署失败且无法自动恢复
- 人工确认需要回滚

### 6.2 回滚步骤

```
1. 删除 NFS 目录
   rm -rf /data/logs/{project}-{env}/
   rm -rf /data/project/{project}/{env}/
   rm -rf /data/project/datastorg/{project}/{env}/

2. 删除 Harbor 项目
   DELETE /api/v2.0/projects/{project}-{env}

3. 删除数据库记录 (软删除)
   通过环境管理页面的“回收”功能执行
```
