# 部署运维手册

> 覆盖：本地开发环境搭建、生产部署（Docker）、Nginx 配置、日志管理、备份恢复、配置项说明

## 本地开发环境

### 依赖

```bash
pip install -r requirements.txt
```

### 依赖服务

- MySQL 8：默认 `root:root@192.168.6.2:3306/ops-platform`，首次启动自动建表并写入种子数据。
- Redis 6+：默认 `redis://:redis@192.168.6.2:6380/1`，认证会话/Agent 心跳/分布式锁依赖。

### 配置

复制配置模板并填写连接信息：

```bash
cp config/config.example.yaml config/config.yaml
```

`config/config.yaml` 包含服务端口、MySQL、Redis 三段启动必需配置，缺失或解析失败时启动直接报错。

### 启动

```bash
python app.py            # http://localhost:8050（debug=False）
```

默认管理员：`admin / admin123`（首次登录后请尽快修改）。

## 生产部署（Docker）

### 镜像构建与启动

```bash
docker compose up -d     # http://localhost:5000
```

- 基础镜像：`python:3.9-slim`。
- 启动命令：`gunicorn -w 4 -b 0.0.0.0:5000 app:create_app()`（4 个 worker）。
- 端口映射：`5000:5000`。
- 挂载卷：`./output:/app/output`、`./templates:/app/templates`。

### 多 worker 注意事项

- 认证会话存 Redis，跨 worker 共享。
- 分布式锁、Agent 心跳、调度概览均基于 Redis，避免多 worker 竞态。
- DDL 同步监听用 Redis 锁防多 worker 重复执行。
- 禁止开启 Flask 自动 reloader（`debug=False`），避免父/子双进程各起一份后台监听线程。

## Nginx 配置

- 平台管理的 Nginx 配置本地存储在 `nginx_configs/` 目录，内容以 MySQL `nginx_configs` 表为准。
- 配置同步：平台通过 SSH 远程同步配置，MD5 校验 + 增量更新，详见 Nginx 配置管理文档。
- 反向代理生产环境时，需为 SSE 接口（如构建日志、调度概览、部署进度、监控流）关闭缓冲，例如：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:5000;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;   # SSE 必须关闭缓冲
    proxy_read_timeout 3600s;
}
```

## 日志管理

| 目录/文件 | 内容 |
|---|---|
| `logs/cicd/` | 构建日志（`{build_no}.log`、`{build_no}.deploy.log`） |
| `logs/database/database.log` | 数据库工具（排序修复/结构同步/DDL 同步）单一日志文件 |
| `logs/` | 部署/回收等任务日志 |
| `server.log` | 开发模式服务日志（生产由 gunicorn/journal 接管） |
| Agent 侧 `{workdir}/logs/agent.log` | 构建节点日志（Agent 启动时截断重写） |

## 备份与恢复

### 需要备份的内容

- MySQL 业务数据：所有表（projects/environments/nginx_configs/cicd_*/users/roles/settings/menus/audit_logs 等）是唯一事实源。
- 配置文件：`config/config.yaml`、`nginx_configs/`（如未完全依赖 MySQL 内容）。
- 平台生成产物可按需备份：`product/`（YAML 产物）、`logs/`。

### 不需要备份

- Redis 认证会话：未强制持久化，Redis 重启后所有用户需重新登录（已接受的取舍）。
- Agent 心跳/调度概览等缓存：可自动重建。

### 恢复步骤

1. 恢复 MySQL 数据。
2. 恢复 `config/config.yaml` 与必要的 `nginx_configs/`。
3. 启动服务，`core/bootstrap.py` 会自动补建缺失字段与种子数据。
4. 用户重新登录（Redis 会话已失效）。

## 配置项说明

| 配置 | 位置 | 说明 |
|---|---|---|
| 服务端口 | `config.yaml` `server` 段 | 默认 8050 |
| MySQL | `config.yaml` `mysql` 段 | 支持 `MYSQL_HOST` 等环境变量覆盖 |
| Redis | `config.yaml` `redis` 段 | 支持 `REDIS_URL`、`REDIS_ENABLED`、`REDIS_KEY_PREFIX` 覆盖 |
| 业务配置 | MySQL `settings` 表 | NFS/Harbor/K8s/Nginx/中间件，系统设置页面维护 |
| Agent 通讯密钥 | `settings` `agent_comm_secret` | 只读，改动会导致所有 Agent 通讯失效 |

## 健康检查

- `GET /health`：返回数据库/Redis 等基础健康状态。
- 平台内「监控」页提供整体健康、单卡监控与 SSE 实时推送（六维度检查见系统管理文档）。

## 安全注意事项

- 默认凭据（MySQL `root:root`、Redis `redis`、管理员 `admin/admin123`）仅限内网环境，生产部署务必修改。
- 认证依赖 Redis 且未强制持久化，Redis 重启后所有用户需重新登录。
- 生产环境建议为 Redis 配置持久化（RDB/AOF）或接受重新登录的取舍。
