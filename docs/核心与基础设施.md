# 核心与基础设施

> 覆盖：core 内核（db / bootstrap / security / audit / redis_client / response）与 config 配置体系

## 目录职责

| 文件 | 职责 |
|---|---|
| `core/db.py` | 全局共享 SQLAlchemy 实例 `db`，供各模块模型与查询统一使用 |
| `core/bootstrap.py` | 建表、字段级自动迁移、菜单与种子数据初始化（内置角色、默认管理员、默认设置） |
| `core/security.py` | 权限校验装饰器、Token 验证、全局鉴权钩子 |
| `core/audit.py` | 审计日志采集、参数脱敏、字段 diff、全局写操作拦截 |
| `core/redis_client.py` | Redis 封装（缓存/锁/计数/集合），异常降级 |
| `core/response.py` | 统一成功/错误响应格式 |

## 配置体系（config/）

启动必需的基础连接配置统一从 `config/config.yaml` 读取，文件缺失或解析失败时启动直接报错。

| 文件 | 作用 |
|---|---|
| `config.py` | 加载 YAML 并生成 `Config` 类（server / mysql / redis 三段） |
| `config.yaml` | 启动必需连接配置（服务端口、MySQL、Redis），不提交到 git |
| `config.example.yaml` | 脱敏示例模板，复制为 `config.yaml` 使用 |

配置优先级：`config.yaml` 优先，其次环境变量（如 `MYSQL_HOST`、`REDIS_URL`、`REDIS_ENABLED`、`REDIS_KEY_PREFIX`）。

业务配置（NFS / Harbor / K8s / Nginx / 中间件等）不从 config 读取，统一存 MySQL `settings` 表，通过「系统设置」页面维护。

## 统一响应格式

所有接口通过 `core/response.py` 返回统一结构：

```json
{
  "code": 200,
  "msg": "success",
  "data": null
}
```

- `success_response(data, msg)`：成功响应，code=200。
- `error_response(msg, code, data)`：错误响应，HTTP 状态码与业务 code 一致。
- 响应 Content-Type 统一为 `application/json; charset=utf-8`。

## 鉴权机制（core/security.py）

### 权限校验装饰器

- `require_permission(perm_code)`：要求当前用户角色拥有指定权限码。
- `require_any_permission(*perm_codes)`：多个权限码任一匹配即可。
- 超级管理员（`super_admins` 独立账号）仅放行系统管理权限集 `SUPER_ADMIN_PERMS`，其余接口一律 403。

### Token 验证

`validate_token` 两步校验：

1. Redis 会话快照校验（token 有效性与滑动续期）。
2. 每次请求实时查 DB，校验用户是否存在、是否禁用、角色权限是否变化——禁用即时拦截、角色变更即时生效，无需重新登录。

Redis 不可用时返回 None（按未登录处理）。

### 全局鉴权钩子

`init_auth` 注册 `before_request`：

- 静态文件与页面路由（非 `/api/`）不拦截。
- 白名单：登录/登出/双因子接口，以及 `/health`、`/api/cicd/agent/` 前缀。
- 超管额外做 `_super_admin_allowed` 全局拦截，只放行系统管理分组与首页/菜单/认证自身。

### Token 提取

- 优先从 `Authorization: Bearer <token>` 请求头。
- EventSource 等无法设置自定义头时，回退 `?token=` query 参数。

## 审计机制（core/audit.py）

### 采集方式

- `record_audit`：同步落库，异常隔离（审计失败绝不影响业务）。
- `register_hooks`：全局拦截器自动记录写操作（POST/PUT/DELETE），`ACTION_MAP` 映射为 create/update/delete。

### 排除规则

- 静态资源、SSE 流、Agent 心跳（`/api/cicd/agent/`）、审计自身查询、认证事件（`/api/auth/` 由 `record_auth_event` 显式记录，避免重复）。
- GET / HEAD / OPTIONS 不记录。

### 脱敏与 diff

- `SENSITIVE_KEYS` 正则匹配密码/密钥/token/私钥/kubeconfig 等敏感字段名，命中即打码。
- 长文本截断（参数 2000、diff 4000）。
- `build_diff` 生成字段级 old/new 差异，供关键更新接口显式调用。

## 数据库初始化（core/bootstrap.py）

- 启动时自动建表（`db.create_all` 语义），并对已有表做字段级自动迁移。
- 写入种子数据：内置角色、默认管理员 `admin/admin123`、默认菜单（`menu_seed.py`）、默认设置。
- 管理员角色启动时自动补全新增权限码，保证拥有全部权限。

## Redis 封装（core/redis_client.py）

- 懒加载连接池（`redis.from_url`，短超时）。
- 所有命令 `safe_*` 包装：Redis 异常返回 None/False 并记日志，不抛出到业务。
- 提供缓存读穿透/写失效、`SET NX PX` + Lua 释放的分布式锁、计数与集合操作。
- 认证会话强依赖 Redis；其余功能在 Redis 故障时降级回源 MySQL / 进程内锁，详见 Redis 使用说明。
